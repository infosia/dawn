# Tint TBDR fork conventions (`feature/tiled`)

This branch is a fork of Dawn/Tint that extends backend coverage for tile-based
deferred rendering (TBDR) shader features. This document records the conventions
that keep the fork **easy to rebase on upstream Dawn** and enumerates every point
where the fork diverges from upstream. The design rationale lives in `TILED.md`
(repo root); this file is the operational rebase aid.

## The `tint-tbdr:` marker convention

Every edit to an **upstream-shared file** is fenced with a pair of marker
comments:

```cpp
// tint-tbdr: begin <tag>
... fork code ...
// tint-tbdr: end <tag>
```

`core.def` uses the same markers with `//` line comments. A single command
enumerates the entire divergence surface:

```sh
git grep -n "tint-tbdr:"
```

Rules:

1. **Shared files carry only minimal, additive, marker-fenced wiring.** Bulk
   logic lives in **fork-only files** (no upstream counterpart), which need only
   a single file-level marker.
2. **Additive `Options` fields only** — no wrapper option structs.
3. **Generated files are never hand-edited** and never marker-fenced; they are
   reproduced mechanically (see below) and committed separately.
4. **No panics / no new ICEs on normal paths.** Unsupported shapes return
   `Failure(...)`; backends that previously rejected a construct with a clean
   `Failure` must not regress to an ICE.

### Generated files (reproduce, never hand-edit)

These are regenerated by `./tools/run gen` from the sources above and are kept in
**separate mechanical commits**:

- `src/tint/lang/core/intrinsic/data.cc` — intrinsic tables (from `core.def`).
- `src/tint/lang/msl/writer/raise/BUILD.{gn,cmake,bazel}` — build file lists
  (from the directory scan that picks up the new fork-only files).

After adding/renaming source files or editing `core.def`, run `./tools/run gen`
(needs Go + network; its Go build cache lives outside the sandbox).

## Scope

- **In scope:** MSL `input_attachment` → `[[color(N)]]`; SPIR-V MSAA
  `input_attachment`.
- **Deferred / out of scope:** the GLSL and HLSL backends; depth/stencil-aspect
  subpass inputs; MSL MSAA subpass input (Metal exposes the sample via
  `[[sample_id]]`, not an explicit index); a per-attachment (rather than global)
  multisampled flag on SPIR-V.

## Rebasing on upstream Dawn

1. `git grep -n "tint-tbdr:"` to list every divergence point.
2. Re-apply the marker-fenced hunks; the fork-only files usually apply cleanly.
3. Drop the generated-file commits and re-run `./tools/run gen` to reproduce
   them against the new upstream base.
4. Rebuild with `-j 1` (high parallelism exhausts memory on the dev machine) and
   run `--gtest_filter='*InputAttachment*'` plus the `*Msl*` / `*Spirv*` suites.
